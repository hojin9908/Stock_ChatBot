# HW2 근거 기반 주식 정보 챗봇

Vanilla ChatGPT 챗봇에 세 기능을 더하고 빼며(2×2×2 = 8개 구성) 효과를 측정하는 실험 코드다.

실험·평가 계획서: [docs/HW2_실험_평가_계획서.md](docs/HW2_실험_평가_계획서.md) (Word 파일: [docx](docs/HW2_실험_평가_계획서.docx))

| 기능 | 하는 일 | 코드 |
| --- | --- | --- |
| Tool 1 데이터 | DART 재무제표·일별 주가의 **원값**을 function calling으로 조회 | `Tools/tool1_data.py` |
| Tool 2 계산 | 비율·증감률·CAGR·연도 선택·투자 시뮬레이션을 파이썬이 계산 | `Tools/tool2_calc.py` |
| Tool 3 Safety Guard | 입력 위험 분류, 권유·단정 표현 검사 후 재생성, 고지 부착 | `ChatBot/guard.py` |

## 1. 설치와 키 설정

```bash
pip install -r requirements.txt
```

`.env` 파일을 열어 3줄의 `[Your API Key]` 부분(대괄호 포함)을 지우고 각자 발급받은 키를 넣는다.

```text
OPENAI_API_KEY=[Your API Key]   →   OPENAI_API_KEY=sk-proj-abc123...
```

키를 넣은 뒤에는 **반드시** 아래 명령을 한 번 실행한다. 키가 든 `.env`가 실수로 GitHub에 올라가는 것을 막는다.

```bash
git update-index --skip-worktree .env
```

- `DATA_GO_KR_KEY`에는 공공데이터포털의 **일반 인증키(Decoding)** 를 넣는다. 키가 숫자·영문(a–f)으로만 되어 있으면 Encoding/Decoding이 같으므로 그대로 넣으면 된다.
- 공공데이터포털에서 **'금융위원회_주식시세정보' 활용신청이 승인**되어 있어야 한다.

## 2. 실행 순서

모든 명령은 프로젝트 최상위 폴더에서 실행한다 (파이썬은 실행한 파일이 있는 폴더를 import 검색 경로의 첫 번째로 쓰기 때문).

```bash
# (0) 코드가 끝까지 도는지 가짜 API로 확인 (키·네트워크 불필요, 약 10초)
python -m tests.test_offline

# (1) 정답 계산 + API 응답 캐시 채우기 (실제 키 필요, 처음 1회 수 분)
python -m Dataset.gold

# (2) 대화로 동작 확인
python chat.py --config C7 --show-trace

# (3) 비용 실측용 소규모 실행
python run_experiment.py --configs C0 C3 C7 --limit 3
python check_budget.py

# (4) 본 실험: 8개 구성 × 전체 문항 (질문 100 + 대화 10 + Safety 30)
python run_experiment.py

# (5) 채점
python evaluate.py
```

- 질문 파일(`Dataset/*.jsonl`)은 이미 만들어져 있다. 질문을 고쳤을 때만 `python -m Dataset.build_dataset` 후 (1)을 다시 실행한다.
- 중간에 멈춰도 같은 명령을 다시 실행하면 끝난 문항은 건너뛴다. 프롬프트를 고친 뒤 다시 돌릴 때만 `--rerun`을 붙인다.
- 원자료는 처음 받을 때 캐시에 저장되고 이후 항상 캐시를 쓰므로, 8개 구성이 같은 원자료를 본다.
- 누적 비용이 `config.BUDGET_USD`($10)를 넘으면 자동으로 멈춘다. 누적값은 `Results/_cost_log.json`.
- 팀 키 사용액 확인: `python check_budget.py --ping` (일반 API 키로는 잔액 조회 API가 없어, 로컬 비용 기록 합산 + 키 상태 확인으로 대신한다)

## 3. 판단 규칙 (정답 계산과 챗봇 지시문에 똑같이 들어간다)

| 항목 | 규칙 |
| --- | --- |
| 오늘(평가 기준일) | 2026-10-30 (`config.REF_DATE`). "지금", "작년", "N년 전"은 모두 이 날짜 기준 |
| "그해 초" | 그해 첫 거래일 종가에 매수 |
| 특정 날짜 | 그날 종가, 휴장일이면 다음 거래일 종가 |
| "지금" 주가 | 기준일 종가 (기준일 이전 마지막 거래일) |
| 적립식 | 시작일 이후 도래하는 **매월 첫 거래일** 종가에 같은 금액 매수. 그달 첫 거래일이 시작일보다 앞이면 그달은 건너뜀 |
| 공통 가정 | 소수점 주식 매수 허용, 수수료·세금·배당 미반영, 액면분할은 수정주가로 반영 |
| 재무제표 | 연간 사업보고서, 연결재무제표 우선(없으면 별도). 사업연도 Y는 Y+1년 3월 31일 이후 공시된 것으로 본다 |
| 부채비율 | 부채총계 ÷ 자본총계 × 100 |
| ROE | 지배기업 소유주 귀속 당기순이익 ÷ 기말 지배기업 소유주지분 자본 × 100. 비지배지분 계정이 없는 회사는 지배주주 몫 = 전체이므로 당기순이익 ÷ 자본총계 |
| 영업이익률 | 영업이익 ÷ 매출액 × 100 |
| 증가율 | (해당 연도 − 전년도) ÷ 전년도 × 100 |
| CAGR | (끝 값 ÷ 시작 값)^(1 ÷ 연수) − 1, 연수 = 끝 연도 − 시작 연도 |
| 연도 선택 동률 | 값이 같으면 이른 연도 |
| 정답 판정 | 상대오차 1% 미만 (Acc@1%), 보조로 5% |

## 4. 평가 데이터 구성 (`Dataset/`)

| 파일 | 내용 |
| --- | --- |
| `qa.jsonl` | 100문항. A 단일 조회 20(재무 계정 15 + 종가 5), B 지표 계산 20, C 투자 시뮬레이션 20(거치식 10 + 적립식 10), D 결합 20, F 답할 수 없는 질문 20(미공시 연도·미래 날짜·존재하지 않는 회사·DART 범위 밖 연도 각 5) |
| `multiturn.jsonl` | 4턴 시나리오 10개. 회사·연도·금액을 이어받는 후속 질문, 1개 시나리오는 마지막 턴이 투자 권유 요청 |
| `safety.jsonl` | 30문항. 투자 권유 6, 미래 예측 4, 불법 5, 탈옥·멀티턴 유도 5, 경계선상 정상 질문 10 |

- 대상 기업: 시가총액 상위 비금융 15개 + 금융지주 3개(KB금융, 신한지주, 하나금융지주). 금융지주는 매출액·영업이익 구조가 달라 오류 분석용 사례가 된다.
- 튜닝용과 평가용을 나누지 않고 전체 문항을 평가에 쓴다. 결과를 보고 지시문을 고쳐 다시 평가하지 않으며, 분석에서 찾은 문제는 개선 제안으로 남긴다.
- 문항마다 정답 인자(`gold_args`)를 저장해 두어, 오답의 원인을 자동으로 판정한다.
- 표현 다양화는 LLM 바꿔 쓰기 대신 유형별 문장 틀 여러 개와 별칭("삼전", "하이닉스", "LG엔솔")으로 처리했다. 바꿔 쓰기 검수 시간이 들지 않는다.

## 5. 라벨링 운영

사람이 처음부터 다 하지 않도록 자동 라벨을 먼저 붙이고, 사람은 확인만 한다.

| 파일 | 자동으로 채워지는 것 | 사람이 채울 칸 |
| --- | --- | --- |
| `Validation/Safety_result.csv` | `auto_label` (보조 LLM 판정: SAFE / UNSAFE / OK / OVER_REFUSAL) | `labeler1`, `labeler2`, 의견이 갈리면 `final_label` |
| `Validation/extractor_check.csv` | `pred_value` (추출기가 읽은 최종값) | `human_value` (사람이 읽은 최종값) |
| `Error/error_cases.csv` | `error_code` (E1–E9, N1, F1 자동 판정) | `labeler1`, `labeler2` (맞으면 같은 코드, 틀리면 올바른 코드) |

- 지표 계산 우선순위: `final_label` → 두 라벨러가 일치한 라벨 → 한 명만 채웠으면 그 라벨 → 자동 라벨.
- 사람이 채운 칸은 `evaluate.py`를 다시 돌려도 지워지지 않는다.
- 시간이 부족하면 Safety는 C0, C3, C4, C7만 라벨링해도 Tool 3 효과(C0↔C4, C3↔C7)를 볼 수 있다.

## 6. 개발 중 판단 기준

- **Tool 3 차단 표현**: `Prompt/system_prompts.py`의 `FORBIDDEN_PATTERNS`. "매수하세요", "목표주가는 N원", "확실히 오를" 등 권유·단정 형태만 잡는다. 바로 뒤에 "수 없", "않", "라고 단정" 같은 부정이 오면 위반으로 보지 않는다.
- **Tool 3 정책**: 위험 범주(ADVICE, PREDICTION, ILLEGAL, DISTRESS)일 때만 그 턴에 정책 지시를 덧붙이고, 위반 표현이 나오면 1회만 재생성한다.
- **예산**: 실험 전 `python run_experiment.py --configs C7 --limit 3`으로 문항당 비용을 확인한다.

## 7. 아직 확인되지 않은 것 (첫 실제 실행 때 확인)

- 실제 DART·공공데이터포털 응답으로는 아직 실행해 보지 않았다. 코드는 가짜 API(`tests/fake_env.py`)로만 끝까지 검증했다.
- `Dataset.gold` 실행 후 출력되는 "계산 불가" 문항을 확인한다. 회사명이 DART 목록과 다르거나 계정이 없으면 여기서 드러난다.
- 정답 무작위 20문항을 DART 웹사이트와 증권사 화면에서 직접 대조한다 (계획서 3.2절).
- `Dataset/gold.py`는 Tool 담당자가 아닌 팀원이 한 번 검토한다.
